# Retrieval Eval Lab

Локальная лаборатория оценки поиска для RAG. Сравнивает пересечение слов и BM25 на одном наборе размеченных запросов, показывает Recall@k, MRR@k и найденные документы для каждого запроса. Ключи API и загрузка моделей не нужны.

## Запуск

Python 3.11+; команды выполняются из корня репозитория.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
pytest -q
ruff check .
```

```bash
retrieval-eval examples/devops.json --k 3
retrieval-eval examples/devops.json --k 3 --min-recall 0.8
```

Порог применяется к среднему Recall@k BM25: при регрессии команда завершится с кодом 1. Ошибочный датасет даёт код 2.

## Формат данных и метрики

`documents`: объекты с уникальными `id` и `text`. `queries`: `id`, `text`, список `relevant` с ID релевантных документов. Пример находится в `examples/devops.json`.

Recall@k — доля релевантных документов среди первых k результатов. MRR@k — среднее значение обратного ранга первого релевантного результата; если его нет, вклад равен нулю. Запросы без релевантных документов отклоняются. Равные оценки сортируются по ID для воспроизводимости. Документы с нулевой оценкой не выдаются.

## Инженерные решения

BM25 реализован непосредственно: k1=1.5, b=0.75. Такая реализация удобна для разбора формулы и проверки поведения, но пересчитывает статистики для каждого запроса. Для больших корпусов нужен отдельный индекс. Тайминг включает построение статистик; это демонстрационный замер, не бенчмарк промышленного поискового сервиса.

Небольшой синтетический DevOps-набор проверяет работоспособность. Его результаты нельзя переносить на реальное качество RAG. Здесь оценивается retrieval, без генерации ответов и LLM judge. Токенизация Unicode по словам, без стемминга и семантических embeddings.

Следующие задачи: адаптер dense retrieval, размеченный независимый test split, nDCG, сравнение сохранённых отчётов и bootstrap confidence intervals.
